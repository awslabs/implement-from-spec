Python (AWS Lambda handlers, Strands agents on Amazon Bedrock AgentCore, a shared library), implementing specification items with pydantic models, boto3 and Powertools. Look hardest at:
- Fidelity to the specification items and the plan's Global constraints: module paths, function, model and field names, error codes, metric and event names exactly as stated; anything missing, stubbed, hard-coded to the happy path or not wired into the code path that runs
- Idempotency and concurrency: handlers that misbehave on a duplicate event; writes without the condition or fence the items require; a fence ConditionCheck on the same item as a Put or Update; TransactionCanceledException reasons not mapped by index; idempotency keys that are unbounded or not the business key
- Silent failures: broad except blocks, swallowed errors, a batch that reports success after a record failed, fallbacks that hide a logic bug, error handling that branches on the message instead of Error.Code
- Boundaries: external input not parsed into a pydantic model with extra="forbid"; request fields bound onto stored or privileged objects (owner, tenant, role)
- AWS clients created per invocation, invocation data in globals, legacy or implicit retry mode, 60-second default timeouts, missing pagination, high-cardinality metric dimensions
- Injection: untrusted input or model output reaching SQL or query text, a shell or subprocess argument, eval, exec or a dynamic import, a template, a format string, a regular expression, an HTTP or mail header, a NoSQL, LDAP or XPath query, a DynamoDB expression or PartiQL statement; output not encoded for where it is rendered; a CSV or spreadsheet cell that can start with a formula character
- Deserialisation and XML: pickle, marshal, shelve, joblib or torch.load on data another party wrote; yaml.load without a safe loader; standard-library or lxml XML parsing of untrusted documents with entities, DTDs or network access left on
- Cryptography, randomness, TLS and secrets: random instead of secrets for tokens; MD5 or SHA-1 for security; passwords under a fast digest; secrets compared with ==; verify=False or an unverified SSL context; an outbound call without a timeout; secrets in code, defaults, environment values, logs, prompts or fixtures
- Authentication, sessions and authorisation: a JWT accepted without a fixed algorithm, a key from a configured source, and checks of aud, iss and exp; cookie flags; session fixation; an object, tenant or tool reached by an id from the request or the model with no ownership or tenant check; identity taken from the request instead of the authentication context; routes or mounted apps not denied by default
- Web surface: debug mode or a development server in production; CSRF switched off where browsers send credentials; CORS with credentials for any origin; open redirects; trusted Host or forwarded headers; unbounded request bodies and uploads; files served from caller-chosen paths
- Files, input, outbound requests, logs and failure: path traversal and archive extraction without filter="data"; temporary files; unbounded reads, decompression, caches and queues; a caller- or model-chosen URL reaching an HTTP client (SSRF); a costly operation with no per-caller limit; sensitive data or line breaks in logs, traces, errors or reprs; assert as a security check; a check that fails open
- Agents and AWS: model output passed on as trusted; untrusted content reaching a model that holds tools; tools acting beyond the caller's permissions or without the human approval the items require; credentials passed to clients in code; presigned URLs issued before the authorisation check; S3 event keys used without URL-decoding; SNS messages accepted without signature verification; AssumeRole for a customer without an external ID
- Runtime and dependencies: a deprecated or preview Lambda runtime or an end-of-life Python line, the AWS SDK for Python developer preview in production code, a dependency or lock file change the plan does not name, an unpinned or unlocked dependency, a constraint that lowers a transitive package, a plain-HTTP or extra index, removed hash checking, an install step that fetches and runs code, credentials in installer configuration
- Known vulnerabilities: a library API used in the way a known CVE exploits, or a dependency version you believe is vulnerable: name the distribution (its PyPI name) and say "verify against the advisory data" rather than asserting, because your knowledge of advisories is dated and the review's dependency audit checks the locked versions
- Types: holes mypy strict cannot see (Any or cast hiding a real path, a type: ignore or noqa hiding a defect, a file the gate excludes), naive datetimes, float where Decimal is needed
- Tests that would still pass if the implementation were removed or broken; missing fault tests for documented error codes; moto clients created before the mock
- Temporal compatibility: old and new versions running side by side, migration or backfill order, replay of events written before the change, rollback after the new version wrote data, partial deployment
- A specification item or test case edited by this change that no approved plan item or amendment covers (an unapproved requirement change)
- For every finding, the evidence as a causal argument: what triggers the defect, the path it takes (file:line steps) and the wrong result; mark a defect that exists on the base independently of this change "pre-existing"
- Library behaviour you are not sure of (Powertools, Strands, pydantic, boto3): say "verify against the docs" rather than asserting
- Precedence: the repository rules, the specification items and the approved plan override these defaults; a deviation the project prescribes is not a finding, except that no rule or plan line waives a security hazard
