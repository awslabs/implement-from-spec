# Template: `specification/TRACEABILITY.md`

This document has no template to fill in: it is the output of the plugin's script and is never edited
by hand. It is never drafted either (`spec-layout.py check` fails a draft that holds it): the last-wave
sync task generates it once the code and tests of the change exist. The script prints the report as
UTF-8 on stdout, and only on a clean run, so it goes into a temporary file under `ai-planning/` (never
inside the draft) and a separate call moves it into place only on exit 0:

    python3 -I "<PLUGIN_ROOT>/core/scripts/spec-layout.py" traceability --repo <REPO> --plan <REPO>/ai-planning/<slug>.plan > <REPO>/ai-planning/<slug>.traceability.tmp
    mv <REPO>/ai-planning/<slug>.traceability.tmp <REPO>/specification/TRACEABILITY.md

The report opens with "Generated by the implement-from-spec plugin", gives a summary (items, items cited
by at least one test, items cited by no test), then one entry per item with the test files and the code
files that cite its ID and the number of citing lines, and lists struck items apart. It carries no date
or commit, so the same tree gives the same report, and names taken from the repository are escaped. A
test or a source file cites an item by its exact ID in a comment, a docstring or a test name.

`spec-layout.py check` fails a report with the generated mark that differs from what the script prints
now, so it is regenerated after the items, the tests or the code change. A symlink at the report's path
or a parent of it stops the check and the script (exit 2). A `TRACEABILITY.md` without the mark is the
project's own report: the check never fails it and the skill never overwrites it.
